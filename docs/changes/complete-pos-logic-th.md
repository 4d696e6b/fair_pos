# สรุปการเปลี่ยนแปลง Fair POS

สาขา: `feat/complete-pos-logic` รวมเข้า `develop` แล้ว  
วันที่: 1 กันยายน 2569  
ผู้จัดทำ: Zen / ทีมพัฒนา

เอกสารนี้อธิบายงานที่เติม logic ให้หน้าจอที่มีอยู่แล้ว ไม่ใช่แค่ UI รวม 6 คอมมิตหลัก

---

## 1. ภาพรวม

ก่อนหน้านี้หลายหน้ามีหน้าจอครบ แต่ปุ่มบางอันยังไม่บันทึกข้อมูล หรือทำงานไม่ครบวงจร รอบนี้ผูกหน้าจอเข้ากับ Firestore / Firebase Auth ให้ใช้งานจริงได้

สิ่งที่เปลี่ยนหลัก ๆ

- ครัวเดินสถานะออเดอร์เป็นขั้น ๆ
- โต๊ะคำนวณยอดจากออเดอร์ทานที่ร้าน และรับชำระเงินสดแล้วปิดบิล
- การเงินแก้ต้นทุนได้
- ประวัติกรองและดาวน์โหลด CSV ได้
- เมนูเปิด/ปิดขายและอัปโหลดรูปได้
- ลูกค้าต้องล็อกอินก่อนสั่ง และเลือกทานที่ร้านหรือกลับบ้านได้
- บัญชีเปลี่ยนรหัสผ่าน อีเมล รูปโปรไฟล์ และลบบัญชีได้
- กระดิ่งแจ้งเตือนในแอปแสดงออเดอร์ล่าสุด
- กฎ Firestore จำกัดการเขียนให้เจ้าของร้านเท่านั้น

---

## 2. คอมมิตที่รวมในรอบนี้

1. บันทึกผู้ปิดออเดอร์ และจำกัดสิทธิ์เขียนข้อมูลร้าน
2. เดินคิวครัว และรับชำระที่โต๊ะ
3. แก้ต้นทุน กรองประวัติ และส่งออก CSV
4. เมนู พนักงาน งานแฟร์ และการเป็นเจ้าของร้าน
5. บังคับล็อกอินตอนสั่ง และรองรับออเดอร์โต๊ะ
6. ความปลอดภัยบัญชี รูปโปรไฟล์ และการแจ้งเตือนในแอป

---

## 3. ความปลอดภัยและโมเดลออเดอร์

### สิ่งที่เพิ่มในข้อมูลออเดอร์

- `completedAt` เวลาที่ปิดบิล ใช้คำนวณเวลาเฉลี่ยบนแดชบอร์ด
- `handledBy` ชื่อผู้ปิดหรือยกเลิกออเดอร์ แสดงในประวัติร้าน

การสร้างออเดอร์ต้องมีผู้ใช้ที่ล็อกอินแล้ว ระบบเกสต์สร้างออเดอร์ไม่ได้ เพราะกฎ Firestore บังคับอยู่แล้ว

### กฎ Firestore / Storage

เขียนร้าน เมนู โต๊ะ พนักงาน และต้นทุนได้เฉพาะเจ้าของร้าน (`ownerUserId`)

ลูกค้าที่ล็อกอินสร้างออเดอร์ได้ อัปเดตออเดอร์ได้ถ้าเป็นเจ้าของร้านหรือเป็นเจ้าของออเดอร์นั้น

รูปโปรไฟล์เก็บที่ `users/{uid}/...` ผู้ใช้คนนั้นเท่านั้นที่เขียนได้

ต้อง deploy กฎขึ้น Firebase เอง:

```
firebase deploy --only firestore:rules,storage
```

ไฟล์ที่เกี่ยวข้อง: `firestore.rules`, `storage.rules`, `src/features/orders/services/orders.ts`, `src/lib/types.ts`

## 4. ครัวและโต๊ะ

### ครัว (`/merchant/[storeId]/orders`)

สถานะจริงตามสคีมา:

รับออเดอร์ → กำลังปรุง → พร้อมรับ → เสร็จสิ้น หรือ ยกเลิก

- ทานที่ร้านที่สถานะพร้อมรับ จะขึ้นว่า รอชำระเงินที่โต๊ะ ไม่ปิดบิลจากครัว
- รับกลับบ้าน กดส่งแล้ว เพื่อปิดบิลจากครัว
- ชื่อผู้กดสถานะถูกบันทึกเป็น `handledBy`

### โต๊ะ (`/merchant/[storeId]/tables`)

สถานะโต๊ะคำนวณจากออเดอร์ทานที่ร้านที่ยังไม่ปิดบิล

- ว่าง ไม่มีออเดอร์ค้าง
- มีลูกค้า มีออเดอร์ที่รับแล้วหรือกำลังปรุง
- รอชำระเงิน ออเดอร์เปิดอยู่ทั้งหมดพร้อมรับแล้ว

ปุ่มรับชำระเงิน (เงินสด) จะปิดออเดอร์ที่ค้างของโต๊ะนั้น แล้วเคลียร์โต๊ะ

ยังไม่มีเกตเวย์ PromptPay หรือบัตร เป็นการปิดบิลเงินสดในร้าน

---

## 5. การเงิน แดชบอร์ด ประวัติ

### การเงิน

ปุ่มแก้ไขต้นทุน บันทึกค่าเช่าบูธ ค่าจ้าง วัตถุดิบ และอื่น ๆ ลง `shopCosts` กำไรสุทธิคำนวณจากยอดออเดอร์ที่เสร็จกับต้นทุนที่บันทึก

### แดชบอร์ด

เวลาเฉลี่ยต่อออเดอร์คำนวณจาก `createdAt` ถึง `completedAt` ถ้ายังไม่มีออเดอร์ที่ปิดบิล จะแสดง —

### ประวัติคำสั่งซื้อ

- กรองช่วงเวลา ทั้งหมด / วันนี้ / 7 วัน
- กรองประเภท ทานที่ร้าน / รับกลับบ้าน
- ดาวน์โหลด CSV ตามรายการที่กรองแล้ว
- คอลัมน์พนักงานใช้ `handledBy`

---

## 6. จัดการร้าน เมนู พนักงาน งานแฟร์

### สิทธิ์เข้าหน้าร้านค้า

เลย์เอาต์ `/merchant/[storeId]/*` ตรวจว่าผู้ใช้ปัจจุบันเป็น `ownerUserId` ของร้านนั้น ถ้าไม่ใช่จะถูกส่งกลับไปหน้า ร้านค้าของฉัน

ไอคอนตั้งค่าบนเฮดเดอร์ร้านพาไปหน้าข้อมูลร้าน

### ข้อมูลร้าน

มีปุ่มลบร้านค้า พร้อมยืนยันก่อนลบ

### เมนู

- สลับมีขาย / หมด ได้จากการ์ดเมนู
- อัปโหลดรูปเมนูตอนสร้างหรือแก้ไข
- เมนูที่หมดจะไม่โชว์ฝั่งลูกค้า

### พนักงาน

ไอคอนดินสอเปิดฟอร์มแก้ชื่อ บทบาท และสถานะ ไม่ได้สลับ active อย่างเดียวแล้ว

บทบาทมีคำอธิบายสิทธิ์คร่าว ๆ (แคชเชียร์ ครัว ผู้จัดการ) แต่ยังไม่ผูกกับบัญชีล็อกอินของพนักงานจริง

### งานแฟร์

หน้า `/merchant` มีปุ่มสร้างงานแฟร์ ร้านสามารถสร้างอีเวนต์ให้ไปผูกในข้อมูลร้านได้

---

## 7. ฝั่งลูกค้าสั่งอาหาร

ที่หน้าเมนูร้าน

- ถ้ายังไม่ล็อกอิน ปุ่มสั่งจะพาไปล็อกอินก่อน
- เลือกรับกลับบ้าน หรือทานที่ร้าน
- ทานที่ร้านต้องเลือกโต๊ะที่ร้านสร้างไว้แล้ว
- สไตล์การขายของร้านจำกัดตัวเลือก เช่น ร้าน takeaway จะไม่มีทานที่ร้าน

หน้าติดตามออเดอร์เปลี่ยนข้อความตามสถานะ รับออเดอร์แล้ว / กำลังเตรียมอาหาร / อาหารพร้อมแล้ว

---

## 8. บัญชีและการแจ้งเตือน

### บัญชี (`/account`)

- อัปโหลดรูปโปรไฟล์ บันทึกทั้ง Auth และ Firestore
- เปลี่ยนรหัสผ่าน (ต้องใส่รหัสปัจจุบัน)
- เปลี่ยนอีเมล ส่งอีเมลยืนยันที่อยู่ใหม่
- ลบบัญชี ต้องใส่รหัสผ่านปัจจุบัน
- สลับโหมดร้านค้าแล้วจำค่าใน `localStorage` และพาไป `/merchant` หรือกลับหน้าหลัก

### กระดิ่งบนเฮดเดอร์

- ยังไม่ล็อกอิน กดแล้วเปิดโมดัลล็อกอิน
- โหมดลูกค้า แสดงออเดอร์ล่าสุดของผู้ใช้
- โหมดร้านค้า แสดงออเดอร์ที่ยังไม่ปิดของร้านที่ตัวเองเป็นเจ้าของ

ยังไม่ส่งอีเมลหรือพุชจริง ค่าตั้งแจ้งเตือนในบัญชียังเป็นแค่การบันทึกความต้องการ

---

## 9. วิธีลองใช้งานสั้น ๆ

ฝั่งร้าน

1. ล็อกอิน แล้วสลับโหมดร้านค้า
2. สร้างร้านหรือเข้าสาขาเดิม
3. เพิ่มเมนู เพิ่มโต๊ะ ใส่ต้นทุนที่หน้าการเงิน
4. รอออเดอร์ที่หน้าครัว แล้วเดินสถานะ
5. ถ้าเป็นทานที่ร้าน ไปหน้ารับชำระที่โต๊ะ

ฝั่งลูกค้า

1. ล็อกอิน
2. เลือกงานแฟร์และร้าน ใส่ตะกร้า
3. เลือกรับกลับบ้านหรือโต๊ะ แล้วสั่ง
4. ดูสถานะที่แท็บออเดอร์ หรือประวัติ /history

---

## 10. สิ่งที่ยังไม่ได้ทำในรอบนี้

- ชำระเงินผ่าน PromptPay / บัตร / Stripe
- พนักงานมีบัญชีล็อกอินและสิทธิ์แยกตามบทบาทจริง
- ส่งอีเมลหรือพุชตามค่าตั้งแจ้งเตือน
- สต็อกจำนวนสินค้า (มีแค่มีขาย/หมด)
- พิมพ์ใบเสร็จ PDF ต่อบิล (มีแค่ส่งออกประวัติ CSV)
